Use my existing Figma design as the EXACT UI reference. Do not redesign, replace, or create a different version of the interface. Implement the actual functionality behind the existing pages and maintain the same layout, components, spacing, colors, navigation, and overall visual style.

USER ROLES:

ADMIN:
The Admin has full access to the entire system. They can search, open folders, upload documents, scan using a connected camera/scanner, create folders, manage document destinations, edit folder formatting/system settings, and view activity logs.

REGULAR USER:
Regular Users have LIMITED access. They can only:

* Search for student records
* Open student folders
* View documents
* Print documents
  They CANNOT upload or scan documents, create folders, change file destinations, edit system settings, or view activity logs.

PAGE 1 — DASHBOARD:
Keep the existing dashboard design. Show archive statistics such as total student folders, documents, and archive status. Use clear status indicators:

* GREEN = Archive Active
* RED = Archive Inactive
  Make the status visually prominent using badges, icons, and subtle backgrounds.

PAGE 2 — SEARCH:
Allow users to search student records using Student ID or student name. Results should show the matching student folder. Clicking a result opens the folder. Regular users can only view/open the folder and documents. They cannot move, rename, delete, upload, or change the folder destination.

PAGE 3 — FOLDERS:
Display student folders using the existing Figma design and folder formatting. Maintain the required alphabetical organization. Opening a folder should show its stored documents and allow authorized users to view and print them.

PAGE 4 — UPLOAD DOCUMENTS / SCANNING:
This is an ADMIN-ONLY function.

Follow the Figma prototype's step-by-step scanning workflow.

STEP 1 — Choose Scan Type:
Allow Admin to choose:

* Student Scan — multiple documents belonging to ONE student
* General Scan — documents belonging to different students

STEP 2 — Identify Student:
For Student Scan, allow the Admin to enter/search the Student ID and student name. Verify the student and show the student information before continuing.

STEP 3 — Add Documents:
Allow the Admin to add documents through:

* Connected camera/webcam
* Scanner device if available
* Existing files from the computer

For camera scanning, implement a REAL camera interface using the device camera. Include camera preview, capture button, retake, and confirmation. After capturing, show the scanned document preview.

Support PNG, JPG/JPEG, and PDF.

STEP 4 — Label Documents:
Show scanned documents in tabs/cards so the Admin can switch between documents. Allow the Admin to assign the document type/label to each document. Student information and document metadata should be stored with the file.

STEP 5 — Review:
Show a complete preview of the documents before archiving. Allow the Admin to go back and correct labels or replace a scan before finalizing.

STEP 6 — Archive:
When confirmed, save the actual document to the correct student folder and destination defined by the system settings. Do not allow Regular Users to change the destination.

STEP 7 — Complete:
Show a success confirmation and update the folder/document statistics.

GENERAL SCAN:
Keep the same step-by-step workflow, but allow multiple documents to be matched to different student records. Allow the Admin to identify each document's student before archiving.

IMPORTANT: Bulk/General scanning must NOT accidentally combine documents from different students into one folder.

PAGE 5 — DOCUMENT VIEWER:
When a document is opened, display the document using the existing Figma viewer style. Allow viewing and printing.

For Regular Users:

* View
* Print
  No editing, uploading, moving, renaming, or deleting.

For Admin:

* View
* Print
* Manage/organize the document
* Perform other authorized archive functions

PAGE 6 — ACTIVITY:
Follow the existing Activity page UI from the Figma prototype.

For Admin, show a detailed activity log containing:

* Person/User who performed the action
* Role
* Date
* Time
* Student folder accessed
* Document accessed
* Action performed
* Status

Examples:
"Maria Santos — Regular User — Viewed folder — DELA CRUZ, JUAN PEDRO"
"Admin — Printed document — Enrollment Form"
"Maria Santos — Viewed document — Transcript of Records"

IMPORTANT: The Admin must be able to see WHO viewed or accessed each folder/document.

Track actions including:

* Login
* Logout
* Search
* Folder viewed
* Document viewed
* Document printed
* Document scanned
* Document uploaded
* Folder created
* Document added
* Document moved
* Document renamed
* Settings changed

Activity records must be automatically generated by the system and READ-ONLY. Users cannot manually edit activity records.

Regular Users MUST NOT see or access the Activity page.

PAGE 7 — SYSTEM SETTINGS:
Use the existing System Settings UI.

System Settings are primarily for FOLDER FORMATTING and archive destination rules.

Regular Users:

* Can VIEW the folder formatting/settings
* Cannot edit anything
* Cannot change folder destinations

Admin:

* Can view and EDIT folder formatting
* Can configure folder naming/formatting
* Can configure archive destinations
* Can manage other archive configuration

Make editable controls disabled/read-only for Regular Users.

STATUS DESIGN:
Improve all activity/archive status indicators:

* ACTIVE = green badge, green icon, subtle green background
* INACTIVE = red badge, red icon, subtle red background
  Use the same visual language throughout the application.

PERMISSIONS:
Do not only hide buttons visually. Implement actual role-based permissions in the backend. A Regular User must still be blocked if they manually enter an Admin URL or API endpoint.

LOGIN → DASHBOARD → SEARCH → OPEN STUDENT FOLDER → VIEW DOCUMENT → PRINT

For Admin:
